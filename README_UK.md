# 🧠 Система пам'яті AI (RLM-Anchor)

> **Довготривала пам'ять для AI-асистентів на основі RLM**

Персистентна система пам'яті для AI-середовищ розробки, заснована на принципах [Recursive Language Models](https://arxiv.org/abs/2512.24601) (MIT-дослідження) (див. [Відео-посібник](https://www.youtube.com/watch?v=huszaaJPjU8)).

> Дайте вашому AI-асистенту **постійну пам'ять**, яка зберігається між чатами.

---

## 💡 Проблема

Кожен раз, починаючи новий чат з AI, він забуває все:
- Архітектуру проекту
- Минулі рішення та їх причини
- Відомі баги та обхідні шляхи
- Ваш стиль написання коду
- Над чим ви працювали вчора

**RLM-Anchor вирішує цю проблему.** Він дає AI структуровану довготривалу пам'ять — у вигляді простих Markdown-файлів прямо у вашому проекті.

## 🌟 Можливості

- **📁 13 організованих категорій** — структуроване зберігання знань проекту
- **🔍 Пошук у стилі RLM** — Examine → Decompose → Recurse → Aggregate
- **🌍 Мультимовність** — відповіді та записи будь-якою мовою
- **⚡ Прості команди** — `/remember`, `/recall`, `/wakeup`, `/sleep`
- **🔄 Передача контексту** — безшовне перемикання між AI моделями
- **📝 На основі Markdown** — читабельно для людей, дружньо до Git
- **🔄 Збереження сесій** — контекст зберігається між сесіями

## 📦 Quick Start & Usage

> ⚠️ **ВАЖЛИВО**: Кожен проект потребує ОКРЕМОЇ установки RLM-Anchor! Використання однієї пам'яті для кількох проектів призведе до плутанини AI через конфліктуючий контекст. Завжди встановлюйте заново для кожного нового проекту.

1. **Імпортуй папку `.agent/`** у свій проект через Git:
   ```bash
   git clone --depth 1 https://github.com/dvgmdvgm/AnchorGravity.git .temp && cp -r .temp/.agent . && rm -rf .temp
   ```
2. **Встанови мову** у файлі `.agent/memory/13_preferences/language.md`
3. **Виконай цей промпт** (скопіюй весь блок нижче):
   ```
   /anchor_agent перевір каталоги поточного проекту на наявність даних, які допоможуть правильно побудувати контекст та налаштувати пам'ять (технічні дані, бізнес моделі, правила дизайну та всі інші типові шаблони для пошуку та збереження контексту проекту)
   ```
4. **Почни роботу** командою чату `/wakeup`.
5. **Працюй у своїй IDE** (розробка, вирішення задач, бізнес рішення, роби все як зазвичай).

*У процесі роботи, на важливих етапах можеш використовувати* `/remember`*, щоб зберегти важливий контекст.*

6. **Коли закінчив роботу** в IDE, наприклад, перед сном, виконай команду `/sleep` для того, щоб RLM-Anchor зберіг контекст у пам'ять.

*Тепер кожен раз коли повертаєшся до роботи над проектом — просто розбуди RLM-Anchor командою* `/wakeup` *і в кінці сеансу знову відправ його спати* `/sleep`*, щоб він запам'ятав все, що ти робив.*

## ⚡ Команди

| Команда | Опис |
|---------|------|
| `/wakeup` | Почати сесію, завантажити контекст |
| `/sleep` | Завершити сесію, архівувати в історію |
| `/remember` | Зберегти інформацію в пам'ять |
| `/recall` | Знайти інформацію в пам'яті |
| `/handoff` | Створити зведення для перемикання моделі |
| `/walkthrough` | Згенерувати документацію фічі |
| `/anchor_agent` | Безпечна інтеграція в проект |
| `/anchor_briefing` | Повний брифінг проекту (всі 13 категорій) |
| `/anchor_backup` | Створити ручний бекап (для перенесення) |
| `/anchor_restore` | Відновити з ZIP бекапу |
| `/anchor_remove` | Безпечне видалення системи (з бекапом) |
| `/anchor_cleanup` | Розумне очищення пам'яті (TTL, scoring) |
| `/anchor_update` | Оновлення до останньої версії з GitHub |
| `/anchor_validate` | Перевірка цілісності пам'яті (5 перевірок) |
| `/memory-stats` | Показати статистику пам'яті з трендами |

📖 **Повна документація команд**: [COMMANDS.md](https://github.com/dvgmdvgm/AnchorGravity/blob/master/docs/COMMANDS.md)

## 🔄 Як це працює

### Процес у стилі RLM

```
Запит користувача
    ↓
┌─────────────────────────────────────┐
│ 1. EXAMINE — Читаємо індекс пам'яті │
│ 2. DECOMPOSE — Визначаємо категорії │
│ 3. RECURSE — Шукаємо в потрібних    │
│ 4. AGGREGATE — Об'єднуємо дані      │
└─────────────────────────────────────┘
    ↓
Контекстна відповідь (налаштованою мовою)
```

## 📝 Приклади використання

### 🚀 Ініціалізація / Підключення
```
Користувач: /anchor_agent
AI: 📋 АНАЛІЗ ІНТЕГРАЦІЇ... [Сканує та пропонує варіанти безпечного впровадження]
```

### ☀️ Почати сесію
```
Користувач: /wakeup
AI: 🚀 Завантажую контекст проекту...
    ✅ Сесію розпочато!
    📌 Незавершених задач: 2
```

### 📌 Запам'ятовування інформації
```
Користувач: /remember Ми обрали PostgreSQL для ACID транзакцій
AI: ✅ Збережено в memory/03_decisions/ADR-002-database.md
```

### 🔍 Пошук знань
```
Користувач: /recall Чому ми обрали PostgreSQL?
AI: 📁 Знайдено в пам'яті:
    Джерело: memory/03_decisions/ADR-002-database.md
    Ми обрали PostgreSQL для підтримки ACID транзакцій...
```

### 🔄 Передача контексту (Handoff)
```
Користувач: /handoff
AI: 🔄 Створюю зведення для передачі контексту... [Генерує зведення для іншої моделі]
```

### 📖 Генерація документації
```
Користувач: /walkthrough Нова авторизація
AI: 📖 Walkthrough створено! Збережено в memory/07_context/walkthroughs/2026-02-05_auth.md
```

### 📊 Статистика пам'яті
```
Користувач: /memory-stats
AI: 📊 Статистика: 42 файли, 13 категорій...
```

### 🌙 Завершення сесії
```
Користувач: /sleep
AI: 📝 Підсумовую сесію...
    ✅ Історію збережено.
    👋 До зустрічі!
```

## 🛠️ Кастомізація

3. Онови `MEMORY_INDEX.md`

### Розширити workflows
Редагуй файли в `workflows/` для кастомізації команд.
