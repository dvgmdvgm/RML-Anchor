# 🧠 Система памяти AI (RLM-Anchor)

> **Долгосрочная память для AI-ассистентов на основе RLM**

Персистентная система памяти для AI-окружений разработки, основанная на принципах [Recursive Language Models](https://arxiv.org/abs/2512.24601)(MIT-исследование) (см. [Видео-руководство](https://www.youtube.com/watch?v=huszaaJPjU8)).

> Дайте вашему AI-ассистенту **постоянную память**, которая сохраняется между чатами.

---

## 💡 Проблема

Каждый раз, начиная новый чат с AI, он забывает всё:
- Архитектуру проекта
- Прошлые решения и их причины
- Известные баги и обходные пути
- Ваш стиль написания кода
- Над чем вы работали вчера

**RLM-Anchor решает эту проблему.** Он даёт AI структурированную долгосрочную память — в виде простых Markdown-файлов прямо в вашем проекте.

---

---

## 🌟 Возможности

- **📁 13 организованных категорий** — структурированное хранение знаний проекта
- **🔍 Поиск в стиле RLM** — Examine → Decompose → Recurse → Aggregate
- **🌍 Мультиязычность** — ответы и записи на любом языке
- **⚡ Простые команды** — `/remember`, `/recall`, `/wakeup`, `/sleep`
- **🔄 Передача контекста** — бесшовное переключение между AI моделями
- **📝 На основе Markdown** — читаемо людьми, дружелюбно к Git
- **🔄 Сохранение сессий** — контекст сохраняется между сессиями

## 📦 Quick Start & Usage

> ⚠️ **ВАЖНО**: Каждый проект требует ОТДЕЛЬНОЙ установки RLM-Anchor! Использование одной памяти для нескольких проектов приведёт к путанице AI из-за конфликтующего контекста. Всегда устанавливайте заново для каждого нового проекта.

1. **Импортируй папку `.agent/`** в свой проект через Git:
   ```bash
   git clone --depth 1 https://github.com/dvgmdvgm/AnchorGravity.git .temp && cp -r .temp/.agent . && rm -rf .temp
   ```
2. **Установи язык** в файле `.agent/memory/13_preferences/language.md`
3. **Выполни этот промпт** (скопируй весь блок ниже):
   ```
   /anchor_agent проверь каталоги текущего проекта на наличие данных, которые помогут правильно выстроить контекст и настроить память (технические данные, бизнес модели, правила дизайна и все остальные типовые шаблоны для поиска и сохранения контекста проекта)
   ```
4. **Начни работу** командой чата `/wakeup`.
5. **Работай в своей IDE** (разработка, решение задач, бизнес решения, делай всё как обычно).

*В процессе работы, на важных этапах можешь использовать* `/remember`*, чтобы сохранить важный контекст.*

6. **Когда закончил работу** в IDE, например, перед сном, выполни команду `/sleep` для того, чтобы RLM-Anchor сохранил контекст в память.

*Теперь каждый раз когда возвращаешься к работе над проектом — просто разбуди RLM-Anchor командой* `/wakeup` *и в конце сеанса снова отправь его спать* `/sleep`*, чтобы он запомнил всё, что ты делал.*

## 🌍 Настройка языка

Редактируй `.agent/memory/13_preferences/language.md`:

```
LANGUAGE=ru    # Русский
LANGUAGE=en    # Английский  
LANGUAGE=uk    # Украинский
...
```

## ⚡ Команды

| Команда | Описание |
|---------|----------|
| `/wakeup` | Начать сессию, загрузить контекст |
| `/sleep` | Завершить сессию, архивировать в историю |
| `/remember` | Сохранить информацию в память |
| `/recall` | Найти информацию в памяти |
| `/handoff` | Создать сводку для переключения модели |
| `/walkthrough` | Сгенерировать документацию фичи |
| `/anchor_agent` | Безопасная интеграция в проект |
| `/anchor_briefing` | Полный брифинг проекта (все 13 категорий) |
| `/anchor_backup` | Создать ручной бэкап (для переноса) |
| `/anchor_restore` | Восстановить из ZIP бэкапа |
| `/anchor_remove` | Безопасное удаление системы (с бэкапом) |
| `/anchor_cleanup` | Умная очистка памяти (TTL, scoring) |
| `/anchor_update` | Обновление до последней версии с GitHub |
| `/anchor_validate` | Проверка целостности памяти (5 проверок) |
| `/memory-stats` | Показать статистику памяти с трендами |

📖 **Полная документация команд**: [COMMANDS.md](https://github.com/dvgmdvgm/AnchorGravity/blob/master/docs/COMMANDS.md)

```
    └── 13_preferences/       # Предпочтения и ЯЗЫК
```

## 🔄 Как это работает

### Процесс в стиле RLM

```
Запрос пользователя
    ↓
┌─────────────────────────────────────┐
│ 1. EXAMINE — Читаем индекс памяти   │
│ 2. DECOMPOSE — Определяем категории │
│ 3. RECURSE — Ищем в нужных файлах   │
│ 4. AGGREGATE — Объединяем данные    │
└─────────────────────────────────────┘
    ↓
Контекстный ответ (на настроенном языке)
```

## 📝 Примеры использования

### 🚀 Инициализация / Подключение
```
Пользователь: /anchor_agent
AI: 📋 АНАЛИЗ ИНТЕГРАЦИИ... [Сканирует и предлагает варианты безопасного внедрения]
```

### ☀️ Начать сессию
```
Пользователь: /wakeup
AI: 🚀 Загружаю контекст проекта...
    ✅ Сессия начата!
    📌 Незавершённых задач: 2
```

### 📌 Запоминание информации
```
Пользователь: /remember Мы выбрали PostgreSQL для ACID транзакций
AI: ✅ Сохранено в memory/03_decisions/ADR-002-database.md
```

### 🔍 Поиск знаний
```
Пользователь: /recall Почему мы выбрали PostgreSQL?
AI: 📁 Найдено в памяти:
    Источник: memory/03_decisions/ADR-002-database.md
    Мы выбрали PostgreSQL для поддержки ACID транзакций...
```

### 🔄 Передача контекста (Handoff)
```
Пользователь: /handoff
AI: 🔄 Создаю сводку для передачи контекста... [Генерирует сводку для другой модели]
```

### 📖 Генерация документации
```
Пользователь: /walkthrough Новая авторизация
AI: 📖 Walkthrough создан! Сохранен в memory/07_context/walkthroughs/2026-02-05_auth.md
```

### 📊 Статистика памяти
```
Пользователь: /memory-stats
AI: 📊 Статистика: 42 файла, 13 категорий...
```

### 🌙 Завершение сессии
```
Пользователь: /sleep
AI: 📝 Суммаризирую сессию...
    ✅ История сохранена.
    👋 До встречи!
```

## 🛠️ Кастомизация

### Добавить новые категории
1. Создай папку в `memory/`
2. Добавь `_index.md` 
3. Обнови `MEMORY_INDEX.md`

### Расширить workflows
Редактируй файлы в `workflows/` для кастомизации команд.
